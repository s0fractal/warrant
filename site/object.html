Objecting to a version

A voice is a challenge against one record, signed with a key of your own and filed in a store of your own. Its actor is that key's name, key:<hex>: the signature verifies under the key whether or not anyone binds it, so nobody can sign in that name and nobody's admission is needed. Nobody can remove it either: it lies in your store, not in the store it objects to.

The publisher's rules do not count it. The lineage's state and reliance in the publisher's store do not move. A reader counts it only under that reader's own rules, when a replayer that reader trusts reproduces it.

A store does not attest its own completeness, and neither does the reader: a voice held in a store nobody reads is seen by nobody.

The steps

From an empty directory, with git and Python ≥ 3.10; node only for reading from a terminal in the last step. The package goes into a venv in that directory, nothing into the system's Python. warrant-graph 3.0.0a7 is the first release with warrant say. VERSION_ID is the full id (64 hex) of the version you object to: the reader shows it on the lineage, in the block «Object to this version», with the commands filled in.

1. The package

python3 -m venv .venv
.venv/bin/pip install "warrant-graph>=3.0.0a7"

2. Say it

.venv/bin/warrant say --store voices VERSION_ID "why this version is wrong"

The directory voices becomes a store of voices on first use: it trusts nobody and gives nobody a role. The key is made on first use; its seed is kept at ~/.config/warrant/commons/commons.seed, and --as NAME keeps another. The command prints the voice's id and its actor, key:<hex>. A store that trusts anyone is refused: a voice is never written into a project's store.

3. Publish it

cd voices
git init
git add .warrant
git commit -m "a voice"

Then push that repository to any host that serves its files over HTTP(S). The store's address is the directory that holds .warrant/; for a public GitHub repository it is its raw address, https://raw.githubusercontent.com/OWNER/REPOSITORY/BRANCH/. That address is VOICES_URL below.

4. Read it

In the reader: open the publisher's store, add VOICES_URL under «Other stores beside this one» (or in the block «Object to this version» on the lineage), and open the lineage. The voice is listed on it among the voices from outside, under its key: actor, not counted by the store's rules. Or from a terminal, with the reader's own file from the repository, STORE_URL the publisher's store and LINEAGE_ID the lineage:

cd ..
git clone https://github.com/s0fractal/warrant.git
node warrant/site/reader.mjs --base STORE_URL --with VOICES_URL --lineage LINEAGE_ID

What it establishes, and what it does not

  • It establishes that the holder of one key said this, against exactly this version, at the time it gives.
  • It does not establish that the objection is right, that anyone read it, or who holds the key.
  • It moves no verdict in the publisher's store. A reader whose rules give a replayer a role, and who reads a store holding that replayer's reproduction of the objection, reads the lineage otherwise under those rules; the reader shows that beside the store's verdict, never in its place.
  • No store and no reader attests that it holds every voice. One left unread is not seen.
