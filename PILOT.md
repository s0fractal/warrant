# Proof-space pilot contract

`warrant-pilot/contract@1`. Generated by `python3 tools/pilot.py project` from `tools/pilot-contract.json`; `tools/pilot.py check` and `tests/pilot_test.py` K1 refuse a differing file.

The pilot of goal G9: a fresh receiver gathers, from content roots and its own configuration only, every object one Sigma receipt needs, checks their bytes, and only then replays the receipt under a verification profile it admits. This contract fixes the terms. The resolution layer (PS-02, PS-03, PS-04) is implemented in `warrant/pilot.py` and tested by `tests/pilot_test.py` (A1-A8, D1-D8, F1-F4, K1-K2); the replay itself and everything after it are deferred to the cards named below.

Scope: the pilot is not part of SPEC.md. It adds no Warrant record type and no engine rule, `engine.assess` does not read it, and the Sigma receipt keeps SPEC §7's members and the meaning of `lost`. A rule below is enforced (cases of `tests/pilot_test.py` that pass, and mutants of `tests/mutants.py` that make them fail), deferred to a filed G9 obligation, or excluded from the pilot.

## The pilot and its receipt (PS-01, duty `d108cd09dd10`)

- **PC-01** The pilot's one proof kind is SPEC §7's `sigma-resume` receipt, unchanged: its dependency fields are read only through `compute.receipt_problem`, so a receipt with another member, a missing one or a malformed hash is refused. *(enforced: D8, D3 · M581)*
- **PC-02** The predicate verified: under an admitted profile p, receipt r is VERIFIED iff SPEC §7's admission holds with p's provider and runtime: target accepted, `lost` empty, `(input, environment)` equal to the condition's, and the receiver's own replay from the root gives NORMAL_FORM with result equal to `claimed` and to the condition's `expect`. A paused, blocked or unavailable replay is not VERIFIED. *(deferred to PS-05+06, duty `637d7124cdb5`)*
- **PC-03** Cycle blobs (`impossible` items) and any second proof kind are outside the pilot; no other kind inherits its labels. *(excluded: a second proof kind is the proposal card PS-14, not filed)*

## Typed addresses and object stores (PS-02, duty `d5cd7a7da4e4`)

A typed address is `<kind>:<hex64>`; the hex64 is the SHA-256 of the object's exact bytes (SPEC §2). The pilot's kinds, each with the tag checked on its bytes and the dependency fields read after it:

| kind | tag, checked on the bytes first | dependency fields (all required) |
| --- | --- | --- |
| `sigma-receipt` | canonical JSON, `receipt` = "sigma-resume" (SPEC §7, unchanged) | `input` (sigma-node), `environment`, `checkpoint`, `state`; `claimed` is a result hash, not a dependency |
| `sigma-environment` | canonical JSON, `schema` = "sigma-resume.environment@draft-1" | each of `hashes` (sigma-node) |
| `sigma-checkpoint` | canonical JSON, `schema` = "sigma-resume.checkpoint@draft-1" | none: the provider replays its chain from the root |
| `sigma-state` | bytes beginning "SGS1" | none |
| `sigma-node` | 34 or 66 bytes, first byte 0x00, 0x01, 0x02 or 0xff (Book I) | none: the environment bounds a node's references (BLOCKED_REFERENCE is the kernel's answer) |
| `pilot-root` | canonical JSON, `schema` = "warrant-pilot/root@1" | each of `requires` (a typed address of any admitted kind) |
| `pilot-profile` | canonical JSON, `schema` = "warrant-pilot/profile@1" | none: its digests are identities |

- **PC-04** Anything but `<kind>:<64 lowercase hex digits>` (`shapes.hex64`) is BAD_ADDRESS, refused before any path is built or any store read: path traversal at the right length, uppercase, a trailing newline. *(enforced: A4, D4 · M571)*
- **PC-05** An object whose bytes hash to its address but lack its kind's tag is KIND_MISMATCH, refused before its dependency fields are read. JSON kinds are canonical bytes (`jcs.loads`): other bytes are refused, never normalized. *(enforced: A3, F4 · M570, M593)*
- **PC-06** A record id is no object address (a store's `records/` is never read), and a record envelope named by its digest is not an object of any pilot kind. *(enforced: A5 · M570)*
- **PC-07** The receiver consults its configured local stores in order: layout `blobs` (`<dir>/<hex64>`, a Warrant store's `blobs/`) and layout `fanout` (`<dir>/<2 hex>/<62 hex>`, a warrant-agent object store). Only a regular file inside the store's real directory is an object of that store: a symlink, a path through a symlinked directory or a directory is not. *(enforced: A1, A6 · M591, M572)*
- **PC-08** One typed address resolves to the same bytes and the same closure id through either store, both, or stores that each hold part of the closure; the closure manifest names no store. *(enforced: A1 · M591)*
- **PC-09** Bytes a store holds under a name that do not hash to it are DIGEST_MISMATCH naming that store, refused before any kind reads them; no other store is consulted past them. *(enforced: A2 · M568, M569)*
- **PC-10** Nothing is fetched from outside the configured stores: no network, no store an object names. *(excluded: a network resolver is the proposal card PS-12, not filed; `warrant/pilot.py` opens only files of configured stores)*

## The closure before verification (PS-03, duty `61f38a12298e`)

The closure of a root is every object reachable through the dependency fields of the table above, walked depth first. Every dependency field is required; the pilot has no optional one.

- **PC-11** Every dependency field of the kinds table is followed: a receipt's `input`, `environment`, `checkpoint` and `state`, an environment's `hashes`, a root's `requires`. A missing object anywhere in the closure is MISSING at its address. `claimed` is a result hash, not a dependency. *(enforced: D1, D2 · M580)*
- **PC-12** Verification starts only on RESOLVED: `Receiver.check` calls the verifier once with the whole closure, and on any other result never calls it and answers the resolution. A result other than RESOLVED carries no object. *(enforced: D3 · M574)*
- **PC-13** A shared dependency is read once; every reference followed counts toward `pilot_edges`, repeats included, so repeated references do not escape the aggregate limit. *(enforced: D1, D6 · M592, M576)*
- **PC-14** An address met again on its own reference path is CYCLE. SHA-256 addresses cannot form a cycle; the guard is shown on a stand-in fetch, and a diamond is not a cycle. *(enforced: D5 · M575)*
- **PC-15** Dependency fields are read with the kind's exact shape: a receipt or root with another member, an environment out of order, a root naming an address twice or nothing is MALFORMED. *(enforced: D8, A8 · M581, M582)*
- **PC-16** A kind the receiver does not admit is UNKNOWN_KIND, at the root or as a dependency, also a kind `warrant/pilot.py` knows. *(enforced: A7, D4 · M573, M600)*

## Resource bounds (PS-03, duty `61f38a12298e`)

The receiver's limits (`warrant.limits.resolve` over these defaults; a receiver sets each one in its configuration):

| limit | default |
| --- | --- |
| `pilot_objects` | 10 000 |
| `pilot_bytes` | 268 435 456 |
| `pilot_depth` | 64 |
| `pilot_edges` | 100 000 |

- **PC-17** Within every limit a closure resolves as without limits; beyond one the result is LIMIT with `limit`, `value` and `bound`, and no object. Objects and bytes are admitted before an object is read; `pilot_depth` bounds the longest chain of references from the root whatever the order of the walk. *(enforced: D6, D7 · M576, M577, M578, M579)*

## Result meanings (PS-03, duty `61f38a12298e`)

RESOLVED establishes that every object of the closure is present in a configured store and is what its address says: byte identity under the address scheme, nothing about the objects' truth, signatures or authority, or the computation's result. INCONCLUSIVE means this receiver could not decide; REFUSED that the objects as presented are not admissible. Neither refutes a proof.

| result | codes |
| --- | --- |
| RESOLVED | none |
| INCONCLUSIVE | `MISSING`, `UNKNOWN_KIND`, `LIMIT` |
| REFUSED | `BAD_ADDRESS`, `DIGEST_MISMATCH`, `KIND_MISMATCH`, `MALFORMED`, `CYCLE` |

- **PC-18** Each code has the one result of the table: a missing object, an unadmitted kind and an exhausted limit are INCONCLUSIVE; a bad address, a digest or kind mismatch, a malformed object and a cycle are REFUSED. *(enforced: D2, A5, A6, A7, D4 · M583, M600)*
- **PC-19** The results of verification itself (VERIFIED, and an unsupported profile or an unavailable operand never becoming VERIFIED) and their independence from duties, grants and acceptances. *(deferred to PS-05+06, duty `637d7124cdb5`)*
- **PC-20** A verified result grants no Warrant authority or permission: use is the receiver's own policy, view and freshness basis. *(deferred to PS-07, duty `cebe8e77a8bc`)*

## Verification profiles (PS-04, duty `1b10e89d75fe`)

A profile is canonical JSON `{schema: "warrant-pilot/profile@1", rule, runtime, verifier: {entry, boot, protocol, provider, modules}, axioms, assumptions}`. `boot` is the digest of the boot script that runs the provider (`compute.BOOT`), `modules` the digest of each provider module, `provider` the identity those digests give (`compute.identity_of_files`). Pinned bytes appear only as digests; host conditions only as text in `assumptions`.

- **PC-21** A profile's id is the SHA-256 of its canonical bytes, which is its `pilot-profile` address; the receiver recomputes it from the bytes it resolved. `pilot.profile` builds one from the receiver's own installed provider. *(enforced: F1 · M588)*
- **PC-22** Changing any declared semantic operand alone (entry, boot, protocol, a module digest, rule, runtime, an axiom, an assumption) gives a valid profile with another id; the old profile stays separately addressable. *(enforced: F2 · M588)*
- **PC-23** A profile with a member missing or added (an unpinned URL), a pin that is not a hex64 digest (a path, URL, ref, uppercase), a provider other than its module digests give, or axioms and assumptions that are not non-empty sorted lists of distinct strings is MALFORMED. *(enforced: F3 · M584, M585, M586, M587, M589)*
- **PC-24** The execution-profile assumptions of the pilot's replay are declared, not pinned: the provider runs as its captured module bytes in a separate CPython interpreter (`-I -B`), which is not an OS sandbox, and a host limit or timeout is inconclusive. `pilot.profile` declares them (`pilot.ASSUMPTIONS`). *(enforced: F1 · M601)*
- **PC-25** Which profiles a receiver admits, and the check that the installed provider is the one an admitted profile pins before a replay runs. *(deferred to PS-05+06, duty `637d7124cdb5`)*

## Receiver-controlled admission (PS-01, duty `d108cd09dd10`)

- **PC-26** Only the receiver's configuration (`Receiver`, `Receiver.from_config`: `warrant-pilot/receiver@1`) chooses the stores, the admitted kinds and the limits; a configuration with anything else is refused, and no object can add a store, kind or limit. *(enforced: A7, A8 · M573, M582)*
- **PC-27** Fetched verifier code is never executed: the pilot runs only the receiver's installed provider (`compute.Provider`). *(excluded: running fetched code is the proposal card PS-13, not filed)*

## Later cards

- **PC-28** A portable bundle of root descriptors and the data and verifier-description closure, verified offline without the producer's checkout or store. *(deferred to PS-08, duty `998ddc19a876`)*
- **PC-29** Only a candidate that passes the admitted verifier is exposed as a verified result root of a continuation recipe. *(deferred to PS-09, duty `4dcb3a20bf2b`)*
- **PC-30** Two fresh receiver processes with different client entry points verify a frozen bundle and resume its recipe to the expected root. *(deferred to PS-10, duty `742f0e621e4f`)*
- **PC-31** A retention root keeps every required reachable object through collection until it expires or is released; a lost unretained object is named unavailability. *(deferred to PS-11, duty `97b0f7d12771`)*
- **PC-32** The pilot's evidence maps each admission, integrity, closure, replay and use boundary to a negative vector lost under a named mutation, with no empty, skipped or crashed case credited. *(deferred to PS-15, duty `acb91af7e549`)*

## Trusted assumptions

- SHA-256 is collision resistant for every address a closure names.

- The receiver's configuration and its installed provider are the receiver's own; nothing a store or an object says changes them.

- A local store may be damaged or changed under the receiver: the digest check detects it at read time and prevents nothing; the pilot keeps no copy (retention is PS-11).

- The process boundary of the provider is not an OS sandbox (SPEC §7).
