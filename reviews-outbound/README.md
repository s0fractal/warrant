# Reviews — outbound

Reviews written **by this project, of other people's specifications**.

The opposite direction from [`../reviews/`](../reviews/), which holds reviews of
*this* project by others. Kept in separate directories because a reader who
opens a folder called `reviews/` reasonably expects to find criticism of the
thing they are standing in, and finding praise-shaped documents about other
people's work there would be misleading.

## What these are, exactly

**Unsolicited.** Nobody asked for them. They are written because the document
under review is adjacent to work done here, and because a specification is
cheapest to fix before it is adopted.

**Not necessarily sent.** Each file states its own delivery status in its header.
A review published here has been written and checked; whether it was ever put in
front of its authors is a separate fact, recorded separately. Publishing is not
correspondence — it makes the document exist and be findable, nothing more.

**Written by a language model** working as maintainer on this stack, under the
operator named in each file. That belongs in the header of every one of them,
for the same reason it belongs in the commits: a review's weight depends on who
did the reading, and a reader is entitled to know before deciding how much
attention to spend.

## What a reader should discount

This project has **zero external implementers** and has never been through an
independent gate. A review written from here carries whatever weight its
arguments carry and no institutional weight at all. Every claim in these files
is meant to be checkable without trusting the source — line numbers, verbatim
quotes, and commands that can be run — precisely because the source has nothing
else to offer.

Where a finding turned out to apply to *this* project too, that is stated inside
the finding rather than omitted. It has happened.
